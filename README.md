# 简历网申助手 · job-apply

一个供 Codex 使用的 Skill：给出简历附件、目标公司或岗位，根据公司的题目要求改写并填写网申。填完后向你展示实际内容，确认后才提交；缺失信息集中问一次，补充答案保存在本地，下次复用。投递记录网页让你查看申请进度、填写内容和招聘链接。

同一个问题只问一次。提问前会查已保存答案和已问记录；等待、部分回复或任务恢复后，剩余信息留在同一待补清单，不在进度更新和结尾重新催问。换任务、拆分字段或更换问题编号也不会重新询问。没有答复就保存草稿，等你主动补充。同一份完整填写版本只请求一次提交确认；实际内容修改后才核对新版本。

启用本人即时通信提醒后，问题满三分钟未答时可通过本机 Hermes 给你发一条 Telegram 提醒。你可以在手机上补充普通信息；发送这一次提醒后就停止自动唤醒，不每隔几分钟检查回复。你主动回来继续时再处理补充信息。

## 使用

安装后，在 Codex 中附上简历并发送：

> 使用 $job-apply，帮我投递 Example 的后端开发岗位，岗位链接是……。用 Chrome 打开，手机号是……。根据题目改写简历内容，填完给我核对，确认后再提交，并更新投递记录网页。不知道的信息问我，补充答案保存下来。

也可以只提供公司名，不必先找招聘网址。Skill 会通过 Google 搜索；Google 无法使用时改用 Bing，不使用百度。找到后核实公司官网招聘入口；如果岗位不明确，会请你选择，再继续申请。

控制提交范围：

- “帮我投递这个岗位”：先填写并展示完整结果，等你确认这一版后提交。
- “帮我填好，先别提交”：填写完成后停在提交前。
- “这段改成……”：改写并更新实际表单，再展示新版本供你确认。
- “把我的通知期改成两个月”：更新资料，下次在适用范围内直接使用。
- “这条答案只用于本次，不要保存”：只在当前申请中使用。
- “忘记我的手机号”：删除资料文件中的对应字段。

## 工作流程

1. 读取本次简历及已有资料；未提供招聘网址时先用 Google，无法使用则用 Bing，自行找到并核实公司官网或官网跳转的招聘平台。
2. 使用指定浏览器和正确账号；需要时使用手机号登录。
3. 手机登录优先使用实际出现的系统验证码填充，也可尝试通过 Mac“信息”查看当次招聘验证码；其他登录方式则截取当前二维码或认证区域，交给你本人完成，核实已登录正确账号后继续。
4. 按公司、岗位和字段题目调整表达，集中询问真正缺失的信息，记录答案的来源、范围和时间。
5. 从页面核对实际填写结果，逐项展示答案以及改写说明，等待你确认；任何后续内容变化都需要重新确认。
6. 确认后按授权提交，根据确认页、申请状态或申请编号记录结果；提交后超时先核实，不连续重复提交。
7. 更新本地投递记录网页，提供公司招聘入口和岗位详情链接。

简历作为事实依据，不要求机械照抄。例如同一段经历，在“工作职责”中突出实际负责的动作，在“项目成果”中突出有依据的结果，在“技术挑战”中解释真实的问题和解决办法。改写不会改变学校、日期、数值等事实，也不会补造经历或扩大个人职责。

填写核对包含实际字段答案、附件名称和关键选项。确认记录绑定到该份内容的版本；对另一家公司或旧版本的确认不能用于当前申请。网页是只读记录页，不会替你作出确认。

## 手机补充信息

可选功能，需要你自行配置本机 Hermes、Telegram 机器人和自己的私聊接收账号。仓库不会附带作者的接收人、凭据、简历或投递资料。

- 先在当前任务集中询问缺失信息；满 180 秒仍未答时，最多补发一条 IM 提醒。
- 在 Telegram 发送以提醒中问题编号开头的新文本消息，补充普通事实；只点消息的“回复”不足以关联问题。
- 提醒尝试结束后立即停止该批问题的后台任务；没有回复也不周期性唤醒，部分回答不会引发新一轮催问。
- 说“不要反复问”或“取消跟进”会关闭当前跟进，草稿和已填写内容保留。
- 验证码和最终提交确认仍回到设备或当前 Codex 任务处理，IM 不接收验证码或代替提交确认。
- 本机配置在 `notifications.json`，待答状态在 `followups.json`，均在私有资料目录内。Hermes 自身可能保存入站聊天。

脚本内置 Hermes + Telegram 桥接；OpenClaw 等后端需按实际能力另行接入。三分钟提醒需要任务仍在运行，或由支持的宿主线程 heartbeat 完成这一次发送后暂停；仅保存期限不会自动唤醒任务，不默认持续轮询手机答复。配置与完整流程见 [三分钟提醒说明](references/followup-notifications.md)。安装过程中不会创建提醒或发送测试消息。

## 投递记录网页

页面提供：

- 公司和岗位列表，区分已提交、待确认、填写中和需处理。
- 公司招聘入口及岗位详情的可点链接。
- 搜索与状态筛选、最近更新时间和申请编号。
- 展开的逐项填写内容、改写说明和确认状态。

在安装目录运行：

```bash
python3 scripts/dashboard.py build
python3 scripts/dashboard.py serve --port 8765
```

使用服务器输出的本机地址查看。服务只监听 `127.0.0.1`，记录变更后可以刷新；关闭服务后可打开生成的离线 HTML。默认网页位于 `~/Documents/Codex/job-applications/dashboard.html`。完整操作见 [记录网页说明](references/dashboard.md)。

首次没有申请记录时显示空状态，不添加虚构公司。网页和填写详情属于本地个人资料，不随公开 Skill 仓库上传。

工作许可按国家或地区保存，薪资按岗位、地点和单位保存，到岗信息检查有效性。不会把中国岗位的资格答案套到其他国家，也不会把月薪填成年薪。

## 登录认证与浏览器要求

Skill 提供操作规范和本地资料工具，本身不会新增浏览器、短信或系统权限。宿主环境需要可用的浏览器工具；查看 Mac“信息”还需要原生应用控制能力、可访问的消息和对应设备同步条件。

只尝试匹配当前招聘服务、本次请求时间内的验证码。不会为安装测试而查看消息，不扫描短信数据库，也不持久保存验证码。人机验证、设备确认或无法访问短信时，需要你完成对应一步。

不使用手机号登录时，可截取当前页面的扫码二维码、设备确认或登录区域，在当前对话展示给你，并说明具体操作。密码由你在原浏览器输入；二维码必须来自同一登录会话，过期后重新取得。截图只临时用于认证，不放入资料库、投递网页或 GitHub。无法截图时会保留原页面并指明操作位置，不把截图已发送或二维码已扫描当作登录成功。详细流程见 [登录认证步骤](references/verification-code.md)。

## 安装

需要支持本地 Skills 的 Codex。资料脚本使用 Python 3.9+ 标准库，支持 macOS/Linux；Mac“信息”操作只适用于具备相应工具的 macOS 环境。

```bash
mkdir -p ~/.agents/skills
git clone https://github.com/CambridgeZ/job-apply-skill.git ~/.agents/skills/job-apply
```

在 Codex 中使用 `$job-apply`，或直接指定安装目录里的 `SKILL.md`。本地 Skill 的结构和发现方式见 [OpenAI Skills 文档](https://learn.chatgpt.com/docs/build-skills)。

## 资料保存在哪里

默认使用：

```text
~/Documents/Codex/job-applications/profile.json
```

同一个文件保存网申事实、每份实际填写内容、确认版本及申请记录，与 Skill 仓库分开。首次运行初始化为空。也可以指定其他资料文件，但后续调用需继续提供该位置。

- 专用资料目录权限为 `0700`，资料文件及锁为 `0600`。
- 内容为本地 JSON，没有额外加密；不保存密码、验证码、Cookie 或会话令牌。
- 同一字段的不同答案不会无声覆盖；用户明确更正后更新。
- 保存采用文件锁与原子替换，已有 JSON 损坏时不会清空重建。
- 凭证字段名检查只是防误存，无法识别自由文本中的所有秘密。

这个公开仓库只包含 Skill、脚本、文档和虚构测试数据，不包含真实简历、手机号、资料文件、短信或投递记录。`.gitignore` 只是辅助，发布前仍需检查实际提交的文件。

## 资料工具

在仓库或安装目录下运行：

```bash
python3 scripts/profile_store.py init
python3 scripts/profile_store.py lookup contact.phone
python3 scripts/profile_store.py list-applications
```

写入答案和记录通过 stdin 传入 JSON；范围、命令、返回状态及完整格式见 [资料操作说明](references/profile-data.md)。执行写入后应检查结果，只有保存成功才算已记住。

## 验证

```bash
python3 -m unittest discover -s tests -v
```

测试使用临时目录及虚构资料，覆盖字段复用、过期与歧义、答案更正、并发保存、文件权限、损坏数据保护、确认版本、提交证据、网页数据处理及三分钟提醒状态。测试不会访问真实招聘网站、Mac“信息”或发送真实 IM。

已完成本地存储测试和工作流场景审阅；真实招聘网站投递、浏览器上传及短信读取需要在实际申请时验证。
