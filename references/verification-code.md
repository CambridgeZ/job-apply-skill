# 当次招聘验证码

仅在正在执行用户授权的招聘登录时使用本流程。不要为了测试 Skill 而读取“信息”。

## 工具选择

先使用浏览器里确实出现的系统自动填充建议。若需查看“信息”，使用当前会话提供的原生应用控制工具；例如已提供 `mcp__cua_repl` 时，遵循其首次调用规范，通过 `cua.getApp("Messages")` 选择应用，并读返回文档后再操作。不要假设存在没有提供的 Messages MCP、AppleScript 收信 API 或浏览器短信接口。

此 Skill 不自带后台短信收集器。没有原生应用读取能力或权限时，直接请用户提供本次验证码，或在设备上完成验证。正常文字任务不要调用仅供语音会话使用的屏幕上下文工具。

## 匹配范围

- 发送请求后记录招聘服务、目标手机号尾号和发送时间；平台品牌可能是公司授权的招聘系统，先核实对应关系。
- 在应用中尽量定位相关发送者或服务名称，仅查看当前登录所需的最近消息。匹配本次请求之后收到的消息，并检查服务名称、登录用途和网站显示的有效期。消息若显示目标号码，核对尾号；不显示号码时不能凭空补充匹配依据，多号码或多请求无法区分时请用户给出当次验证码。
- 不扫描或导出短信数据库，不批量读取聊天历史、附件或其他验证码。界面偶然显示的无关消息不摘要、不复制、不保存。
- 不用其他服务的代码，不混用上一轮验证码，也不要在聊天回复中复述完整验证码。只将匹配代码填入当前已核实的招聘网站。
- 无法找到可确认匹配的代码时，请用户提供本次代码；不靠不断重发短信碰运气。确需重发时遵守网站倒计时，每轮最多补发一次，重置时间窗口；仍失败就说明具体阻碍并由用户完成。

## 边界与结果

macOS 访问授权、iPhone 与 Mac 消息同步、网页系统填充都可能影响结果。这些条件只有实际登录时才能验证；工具存在不代表已经能读到短信。

不要更改系统权限、登录 Apple ID、修改安全设置或绕过 CAPTCHA 来强行完成。可告知用户具体界面要求并保留当前进度。验证成功以页面确实进入正确账号为准，不以验证码已填入为准。

验证码仅短暂用于认证，不主动写入资料、日志、脚本、输出文件或打包产物；不要承诺浏览器、聊天系统或工具本身绝不留痕。
