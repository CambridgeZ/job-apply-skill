# 选材与页面适配

用于经历、项目、技能、自我评价及开放题起草，或不同页面结构使同一资料需要重新映射时。以下是判断方法，例子中的人物经历均为虚构；不能把示例答案当作申请人的事实。

## 先决定这道题需要什么

读字段原文及附近提示，而非只匹配“经历”“项目”等关键词。结合目标岗位，选能直接回答问题的证据，再决定表达长度和结构。正文应当让招聘者知道申请人实际做了什么，以及这件事为何能说明相关能力。

在工作草稿中为复杂或需改写的字段留一行即可：

`字段/限制 | 题意与岗位要求 | 选用事实及来源 | 最终答案 | 尚缺的实质信息`

这是辅助判断，不是必须向用户展示的额外问卷。用户核对的是页面中的最终内容及简短改写说明。

| 字段意图 | 选材与表达 | 不应填入 |
| --- | --- | --- |
| 工作职责 | 个人承担的动作、组件或流程及责任边界 | 整个团队的目标和产品宣传 |
| 项目成果 | 已实现的能力、交付物、验证结果；指标须有来源 | 只列技术栈，或把目标写成已达成 |
| 技术挑战 | 实际问题、采取的措施、已知取舍或验证 | 凭经验编一个申请人没遇到的事故 |
| 岗位优势/自我评价 | 与 JD 相关的能力及具体证据 | 通用的“学习能力强、抗压、热爱挑战” |
| 求职动机 | 已表达的个人原因；可起草事实支持的岗位匹配部分 | 擅自写长期向往、家庭原因、薪资偏好或入职承诺 |
| 结构化经历 | 单位、职位、日期分别填写；正文说内容 | 每一栏都粘完整简历段落 |

### 同一事实，按问题重新组织

虚构素材：申请人实习时为订单接口增加超时重试与幂等键，补充集成测试，在测试环境验证重复请求不会重复创建订单；没有上线收益或性能数字。

- 后端岗位问“主要职责”：`为订单接口实现超时重试和幂等处理，补充重试场景的集成测试。`
- 同一表问“项目成果”：`在测试环境验证重复请求不会重复创建订单，补齐了重试场景的测试覆盖。`
- 测试开发岗位问“相关经验”：`围绕订单接口的重复请求和超时重试补充集成测试，验证幂等逻辑，积累了异常场景测试经验。`
- 问“技术挑战”：现有素材支持说明重复请求问题及幂等处理；如果要求具体事故、权衡方案或个人决策过程，先查其他资料，不能编造生产故障或未说明的方案比较。
- 20 字以内的“特长”：`接口开发、幂等处理与集成测试`。限制变短时保留最相关内容，不要求用户另写一版。

这些答案的变化来自题意和岗位重点。不能据此声称“负责订单系统架构”“保障端到端 exactly-once”“降低故障率 80%”或“已在生产大规模运行”。

## 选择内容，而不是填满内容

先抓住当前岗位最相关的要求，不预设所有岗位都偏爱相同技术。例如业务后端可能重视接口交付和异常处理，数据平台可能重视数据链路和恢复，测试开发可能重视自动化与异常覆盖；只有当前 JD 支持时才采用这些重点。

- 从现有经历中选最有说服力的例子。短栏选核心证据，长栏可以增加上下文和取舍；字数上限不是必须写满的目标。
- “项目描述/职责/成果”同时出现时，让描述交代场景和整体方案，职责说明个人工作，成果交代得到的能力或结果。允许必要上下文重复，避免三栏一字不差或轮流堆同一串技术名。
- 如果已有适配答案，先看新题意是否相同。能直接复用就保留；题意、岗位重点、格式或语言变了才重组。不能把上一家公司正文仅换一个公司名。
- 岗位问到无相关证据的技术时，不把其他技术换名来凑匹配。可选栏留空；明确要求回答时按事实说明范围，缺少实质事实再沿主流程处理。
- 技术表达应符合读者和字段：必要时解释简历缩写，保留区分个人实现与所用平台能力的限定词。公司自身的业务描述不作为个人经历证据。

## 自主处理与需要用户补充的边界

| 情况 | 处理方式 |
| --- | --- |
| 提供了年月，页面只收年月；名称可选上位学科且真实包含原专业 | 自主转换或分类，在专业原文栏保留原名 |
| 提供了年月，网站必须填到日 | 先检查网站约定和已有材料；无法确定具体日期时不能补成 1 日 |
| JD 和用户目标都指向开发，方向选项为“开发/运维” | 依据已有目标选开发并在核对中说明；不把无关岗位偏好默认为永久偏好 |
| 用户刚填了电话或校区，而简历较旧 | 保留有明确来源的新值；记录其来源，避免又问一次 |
| 预填数据来源不明，或显示真正矛盾 | 先比较来源和格式；无法解决的实质冲突按主流程去重后集中询问 |
| 技能短栏超长、年月格式不符、附件类型被拒 | 自行压缩、转换或选用已有合适附件；不得伪称上传成功，也不改造证明文件事实 |
| 英语有考试成绩，但页面要求听说自评；健康、薪资、迁居等未知 | 分数不能自动换算个人自评；只问真正必需且没有来源的个人事实/决定 |
| 可选兴趣爱好或无依据的论文信息 | 留空，不为填满页面推断或问无关问题 |

“自行调整”只改变有根据的表达、映射或操作，不降低事实可靠性，也不替用户作出未授权的决定。

## 页面变化时重新判断

读当前页面的用途、已存在的值、必填约束和控件结果，再选择下一步。下列不是固定网站流程：

- 通用人才库简历只有教育和项目，点击岗位申请后可能新增语言、方向或家庭信息。先展开当前能安全到达的正式表，再汇总缺项和展示完整版本，不能在通用页就报告“已投递”。
- 一个网站把实习放在“工作经历”，另一个网站分开两栏。按页面定义归类，保留“实习生”身份；不能为避免空栏而复制成一段正式工作。
- 选择某学历或国家后出现条件必填，先读新增题意并查可复用资料。已问过的旧字段继续沿用，不因分支变化重新发一遍问卷。
- 控件显示选中但底层原生属性不一致时，检查当前工具可读取的选中样式、可见文字和保存后状态。发现矛盾就核实，不反复点击把正确选择取消。
- 预览给出长度或格式错误时，用既有事实修正后重新回读；最终核对版本应包含修正后的值。若通用页曾获确认而正式表新增实质内容，旧确认不能伪装成新版本确认。

记录和核对基于实际页面值，而非计划填入的草稿。对于人工调整的专业短文，在 `source` 留事实出处，在 `adaptation` 写清选材原因，例如“此岗位强调异常处理，突出已有重试和幂等测试经验，省略无关界面工作”。一句具体说明优于“根据岗位进行了优化”。
